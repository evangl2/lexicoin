### [🟢] Array allocation in requestAnimationFrame hook
- **Symptom**: Slight micro-stutters during panning and zooming on the canvas over time due to garbage collection pauses.
- **Location**: `src/app/hooks/useViewportCulling.ts:84`
- **Root cause**: Checking Set equality by spreading the Set into an Array (`[...next].every(...)`) inside a state update triggered by `requestAnimationFrame`. This creates a new Array in memory every single frame during camera movement, leading to unnecessary memory allocation and eventual GC spikes.
- **Suggested fix**: Replaced the array spread and `.every()` method with a zero-allocation `for...of` loop and a boolean flag to check for Set equality without creating intermediate arrays.
- **Expected gain**: Saves O(N) memory allocation per frame during canvas movement, where N is the number of visible cards.
- **Fix risk**: Low
