### [🟡] Forced Layout Thrashing in useTextFit hook
- **Symptom**: Stuttering or dropped frames when new cards with lots of text appear on the canvas, or when the window is resized.
- **Location**: `src/app/hooks/useTextFit.ts:93`
- **Root cause**: Inside the binary search loop that calculates the correct font size, `getBoundingClientRect()` and `getComputedStyle()` are called repeatedly after setting `style.fontSize`. Because the DOM was just mutated, the browser is forced to synchronously recalculate layout (reflow) multiple times per frame for every text element using this hook.
- **Suggested fix**: Remove the visual safety check (`getBoundingClientRect()`) and `getComputedStyle()` from the loop. Rely purely on `container.scrollHeight > container.clientHeight` and `container.scrollWidth > container.clientWidth` to verify the fit, which doesn't trigger synchronous reflow when read sequentially without mutations in between.
- **Expected gain**: Saves ~5-15ms per frame during text scaling, completely eliminating layout thrashing spikes.
- **Fix risk**: Medium (might slightly change text fitting accuracy in edge cases with extreme ascenders/descenders)

### [🟢] O(N) Array Allocation in libraryGrimoires update
- **Symptom**: Slight CPU spike when claiming rewards or moving grimoires to the archive.
- **Location**: `src/core/store/slices/createProgressionSlice.ts:132`
- **Root cause**: Uses `.map()` on the entire `libraryGrimoires` array when updating a single grimoire's status, creating a new array reference and iterating over all items unnecessarily.
- **Suggested fix**: Replaced with `.findIndex()` to locate the specific item. If found, creates a shallow copy of the array and updates only that exact index.
- **Expected gain**: O(N) single-pass efficiency.
- **Fix risk**: Low

### [🟢] Unnecessary re-renders from Zustand player selector
- **Symptom**: Unrelated components on the canvas update unnecessarily when stamina or XP changes.
- **Location**: Multiple (`src/app/hooks/useGrimoireSummoning.ts`, `src/app/hooks/useEchoSystem.ts`, `src/app/hooks/useGrimoireReward.ts`, `src/app/components/ui/visual/LibraryInterface.tsx`)
- **Root cause**: Components are using `useGameStore(s => s.player)` to extract a single property like `settings`, `stamina`, or `echoCharges`. Returning the entire `player` object causes a re-render anytime *any* player property changes (like `xp` during an animation or `stamina` tick).
- **Suggested fix**: Updated selectors to grab only the precise property needed (e.g., `useGameStore(s => s.player?.settings)` or `s => s.player?.echoCharges ?? 0`).
- **Expected gain**: Eliminates over-rendering on unrelated state changes (like stamina regen causing LibraryInterface to re-render).
- **Fix risk**: Low
