### [🟡] Over-eager persistence of highly dynamic view states
- **Symptom**: Potential stuttering and lag during canvas panning or zooming, especially on lower-end devices.
- **Location**: `src/core/store/index.ts:324`
- **Root cause**: The `canvasView` state (representing pan and zoom coordinates) updates very frequently during user interaction. Including it in the Zustand `partialize` filter means every small movement triggers a write to IndexedDB, causing heavy disk I/O bottlenecks.
- **Suggested fix**: Remove `canvasView` from the `partialize` whitelist in the `useGameStore` creation block so it is not saved to the persistent database.
- **Expected gain**: Dramatically reduces IndexedDB write operations during canvas interactions, keeping the framerate smooth at 60fps.
- **Fix risk**: Medium (might affect how the canvas remembers its position between reloads, requires user approval).
