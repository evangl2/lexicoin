### [🟡] Forced Layout Thrashing in useTextFit hook
- **Symptom**: Stuttering or dropped frames when new cards with lots of text appear on the canvas, or when the window is resized.
- **Location**: `src/app/hooks/useTextFit.ts:93`
- **Root cause**: Inside the binary search loop that calculates the correct font size, `getBoundingClientRect()` and `getComputedStyle()` are called repeatedly after setting `style.fontSize`. Because the DOM was just mutated, the browser is forced to synchronously recalculate layout (reflow) multiple times per frame for every text element using this hook.
- **Suggested fix**: Remove the visual safety check (`getBoundingClientRect()`) and `getComputedStyle()` from the loop. Rely purely on `container.scrollHeight > container.clientHeight` which is significantly faster and doesn't trigger the same level of synchronous reflow when read sequentially.
- **Expected gain**: Saves ~5-15ms per frame during text scaling, completely eliminating layout thrashing spikes.
- **Fix risk**: Medium (might slightly change text fitting accuracy in edge cases with extreme ascenders/descenders)

### [🟢] O(N) Array Allocation during Grimoire updates
- **Symptom**: Micro-stutters during grimoire slot filling, resolving, or state changes on the canvas.
- **Location**: `src/core/store/slices/createGrimoireSlice.ts`
- **Root cause**: Using `.map()` to update a single grimoire's state (e.g., in `updateGrimoire`, `updateGrimoireStatus`). This creates a new array reference every time and iterates over all active grimoires, causing unnecessary React re-renders and memory allocation.
- **Suggested fix**: Use `.findIndex()` to locate the specific grimoire. If found, create a shallow copy of the array and update only that specific index, returning the unmodified previous array if not found.
- **Expected gain**: O(N) single-pass efficiency and reduced React rendering overhead for grimoire interactions.
- **Fix risk**: Low

### [🟢] O(N) Array Allocation in Grimoire Interaction evaluation
- **Symptom**: Slight latency when submitting a grimoire for AI evaluation.
- **Location**: `src/app/hooks/useGrimoireInteraction.ts:102`
- **Root cause**: After receiving AI evaluation results, the hook uses `.map()` to iterate over all grimoire slots and uses `.find()` inside the map to match results. This is O(N^2) for updates and creates intermediate arrays.
- **Suggested fix**: Convert `apiResults` into a `Map` for O(1) lookups, replacing the nested `.find()` inside the `.map()`.
- **Expected gain**: Avoids O(N^2) lookup overhead during grimoire submission results.
- **Fix risk**: Low
