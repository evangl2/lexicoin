### [🟡] Forced Layout Thrashing in useTextFit hook
- **Symptom**: The user might experience brief framerate drops or stuttering when UI elements with dynamic text (like cards being flipped or resized) enter the viewport or change.
- **Location**: `src/app/hooks/useTextFit.ts:70`, `src/app/hooks/useTextFit.ts:98`
- **Root cause**: The `useTextFit` hook performs a binary search to find the optimal font size. Inside the loop, it synchronously calls `window.getComputedStyle(textEl)` and reads `textEl.offsetHeight` / `scrollHeight`. These reads force the browser to recalculate the layout immediately (forced reflow) multiple times per component, causing significant layout thrashing on the main thread.
- **Suggested fix**: Remove the `VISUAL SAFETY CHECK` block and the `getComputedStyle` check inside the loop. Use predefined config or purely CSS-based metrics (like character counting or pre-calculated line heights) instead of forcing synchronous DOM layout recalculations during binary search.
- **Expected gain**: Eliminates redundant synchronous reflows, freeing up main thread capacity to ensure buttery smooth text-resizing and animation at 60 FPS.
- **Fix risk**: High (Can break visual text scaling on cards if not replaced carefully)
