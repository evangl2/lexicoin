## Issues

### [🟡] B-010: Missing Timeout on Edge Function Invocations

- **Symptom**: Sometimes, summoning a grimoire or submitting a grimoire for evaluation hangs indefinitely on a loading state. If the user's connection drops silently, or the AI provider (OpenRouter) stalls during the backend Edge Function, the UI never recovers or shows an error.
- **Location**: `src/app/hooks/useGrimoireSummoning.ts:95` and `src/app/hooks/useGrimoireInteraction.ts:80`
- **Root cause**: The `supabase.functions.invoke()` calls lack a reliable built-in frontend timeout. They wait for the backend to respond, but if the network drops or the Edge Function hangs internally (e.g., waiting for AI generation), the promise never resolves or rejects. `useSynthesis.ts` correctly handles this using a `Promise.race` with a hard timeout, but `useGrimoireSummoning` and `useGrimoireInteraction` do not.
- **Suggested fix**:

```typescript
// Add this timeout pattern before invoking the edge function:
let hardTimeoutId: ReturnType<typeof setTimeout>;
const raceTimeout = new Promise<never>((_, reject) => {
    hardTimeoutId = setTimeout(() => {
        reject(Object.assign(new Error('Request timed out (90s)'), { name: 'AbortError' }));
    }, 90_000);
});

// Update the invocation in both useGrimoireSummoning and useGrimoireInteraction:
try {
    const { data, error: invokeErr } = await Promise.race([
        supabase.functions.invoke('edge-function-name', {
            body: { /* payload */ }
        }),
        raceTimeout
    ]);

    // existing logic...
} finally {
    clearTimeout(hardTimeoutId!);
}
```

- **Expected gain**: Prevents infinite hanging. Users will get a clean "timed out" error message after 90 seconds, allowing them to retry without refreshing the entire application.
- **Fix risk**: Medium — modifies core interaction paths. Requires testing to ensure the fallback UI and state reset (like returning grimoire to ACTIVE state) handle the timeout error correctly.
