### [🟡] NotificationSystem lacks exit animation
- **What happens now**: When a toast notification is clicked or times out, it instantly disappears from the screen without any transition.
- **Why it feels off**: Missing follow-through and settle. The sudden disappearance violates the physical continuity of UI elements, feeling abrupt and unnatural.
- **Location**: `src/app/components/system/NotificationSystem.tsx:16`
- **Proposed change**: Wrap the notifications in Framer Motion's `<AnimatePresence>` and change the notification div to `<motion.div>` with `exit={{ opacity: 0, x: 100 }}` and a spring transition.
- **Why this works**: Providing an exit animation confirms the action (success/failure of dismissing) and lets the element leave the screen smoothly, maintaining physical presence.
- **Confidence**: High

### [🟡] NotificationSystem uses CSS ease-out
- **What happens now**: Notifications slide in using a standard CSS `@keyframes` animation with a linear `ease-out` timing function.
- **Why it feels off**: Missing overshoot and bounce. `ease-out` stops perfectly at its target, feeling robotic rather than physical and snappy.
- **Location**: `src/app/components/system/NotificationSystem.css:35`
- **Proposed change**: Remove CSS animation and replace with Framer Motion spring: `initial={{ opacity: 0, x: 100 }} animate={{ opacity: 1, x: 0 }} transition={{ type: "spring", stiffness: 300, damping: 25 }}`.
- **Why this works**: A spring transition gives the toast weight and a slight bouncy snap when it arrives, drawing attention naturally without being harsh.
- **Confidence**: High

### [🟡] Synthesis error feedback lacks physical response
- **What happens now**: When a synthesis fails, the circle merely displays red status text (`state.errorMessage`) and fires a system toast, remaining completely still.
- **Why it feels off**: Missing secondary motion and squash & stretch. A failure in an energetic, magical process should feel volatile or jammed, not perfectly static.
- **Location**: `src/app/components/ui/visual/SynthesisCircle.tsx:250`
- **Proposed change**: Add a visual "error shake" to the main base container by passing `animate={{ x: state.errorMessage ? [-10, 10, -10, 10, 0] : 0 }}` and `transition={{ duration: 0.4 }}` to the `<motion.div>`.
- **Why this works**: A brief horizontal shake gives a physical jolt to the UI, instinctively communicating "rejection" or "failure" without relying solely on reading text.
- **Confidence**: High
