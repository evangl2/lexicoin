# ADR-011: UI/UX 交互宪法——四层结构、五原则、词卡不设仓库

> 状态: 现行 · 类型: 决策 · 更新: 2026-07-06
> 📖 人话: 整个游戏的交互骨架定案:画布即 UI,拖拽是唯一动词、点击是阅读;界面分四层(世界/檐口/仪式/透镜);词卡**没有仓库**——你的词全在桌上,不用的会自己风化沉降。Stage F–N 所有交互设计以本文为宪法。

## 背景

2026-07-06 作者定案。设计出发点是玩家体验蓝图(ATLAS §2)的核心幻想:儿童好奇心 + 炼金工作台 → 交互哲学为**直接操纵**——手伸进世界摆弄东西,不隔着菜单指挥。渲染实现遵循 [ADR-010](ADR-010-render-boundary-and-tooling.md) 边界三律,本文与其一一对应。

## 决策

### 1. 交互语法(全局唯一)

> **拖拽 = 动词,点击 = 阅读。**

拖卡入阵 = 合成;拖卡入槽 = 填魔典;拖到空地 = 安放。点击/轻点永远是"看"(翻面、发音、检视),永不触发状态变更类动作。核心循环内**不允许出现菜单**。

### 2. 四层结构

| 层 | 技术 | 内容 | 规则 |
|---|---|---|---|
| **世界层** | Pixi | 卡片、装置(Summoner/合成阵)、魔典闭合态、Centerpiece | 一切随相机;直接操纵;唯一语法见上 |
| **檐口层** | 屏幕固定 DOM | 仅四样:体力(具象物,非进度条)、Persona 在场感(角落身影,常驻)、Library 入口、设置 | **檐口上不放功能按钮**——功能都在世界里的装置上;越薄越好 |
| **仪式层** | DOM 覆盖 | 检视态、魔典展开(双页模态)、结算、Library 全屏 | 出场时世界压暗,"进入书页"的仪式感;ESC/点外部永远可退,仪式不困人 |
| **透镜层** | 相机模式 | 记忆透镜(ADR-007)、搜索透镜(见 §4)、分区注解 | 按住看/一键切的**视图**,不是困住玩家的模式 |

### 3. 五条交互原则

1. **渐进披露**:hover 只显示标题(Pixi Text)→ 单击发音 + 翻面简义 → 检视态才有全文。阅读深度由玩家自决——隐形学习在交互层的形态:释义永远在场,从不强塞;
2. **hover 只锦上添花,不承载关键信息**——关键信息必须有点击路径(为触屏留路,触屏无 hover);
3. **等待即演出**(蓝图 2.3 执行):AI 调用一律呈现为装置上的物理过程,永不出现遮罩转圈;长等待不锁画布,完成时装置爆闪 + Persona 开口;
4. **通知人格化**:能让 Persona 开口的不用 toast(ADR-008 §6);系统性事务(存档失败等)才用系统通知;
5. **空状态即引导**:新手引导不做教程弹窗,做成 Persona 的第一次委托(递卡、指阵、"试试")。引导缺口用叙事填,不用 UI 填。

### 4. 词卡不设仓库(作者定案)

词卡**只存在于画布上**,不提供可存取的仓库/收纳容器。理由:

- 仓库与记忆宫殿原理互斥:位置即记忆编码(ADR-007"位置属于玩家"),仓库里的卡没有位置,每收纳一张即销毁一个空间记忆挂点;
- 单一心智模型:"我的词在哪"永远只有一个答案;
- 整理被迫游戏化:唯一整理手段是自画分区——给词分类本身是语义加工,是学习;仓库列表整理是数据库劳动;
- 与记忆模型自洽:不维护的词自动风化沉降,系统以"遗忘"的逻辑替玩家收纳,画布人口 ≈ 活词汇量。

**三个执行条件**:

1. **记忆模型先行**:风化沉降(ADR-007)必须在画布规模成为问题前上线(现行次序已保证:记忆模型排在 Stage F 附近);
2. **搜索透镜为必要配套**(列入 Stage G/H 规划):呼出输入框 → 匹配卡片在画布上发光、相机飞行定位。找卡是搜索需求不是存储需求,卡不离开它的位置;
3. **风化档案严格只读**:凭再遭遇唤醒,绝不做成可主动存取的第二仓库;**不做"主动尘封"手势**——那是手动仓库的后门。画布无限大,暂时不用的卡拖到角落即可。

允许的将来扩展:Library 内的**只读词汇总览**页签(按 CEFR/词性筛选浏览、点击飞行定位)——它是索引不是容器,不违背本决策。

## 理由

- 语法唯一(拖=做,点=看)使玩家学习成本趋零——学的是世界的物理,不是界面的规则;
- 檐口极简与"通知人格化"共同服务 Persona 真实人物感:她在场、她开口,而不是系统弹窗;
- 无仓库把一项管理负担(收纳整理)转化为隐形学习机制(空间分类),是"所有系统为隐形学习服务"(蓝图 2.5)的直接体现。

## 后果

- GDD §2.3 / §5.2 / §6.5 中"从 Canvas **或仓库**拖拽"的表述已修正(同批 commit);
- roadmap Stage N 的"DeckRepository 重新接入"改为**不回归**,组件随 Stage O 删除;store 中 `deckState` 字段与 partialize 白名单项届时一并清理;
- 搜索透镜列入 Stage G/H 规划范围;
- Stage F–N 每个阶段的规划对话必须核对本宪法;新交互不符合"拖=动词/点=阅读"语法的,先修改设计再动工。
