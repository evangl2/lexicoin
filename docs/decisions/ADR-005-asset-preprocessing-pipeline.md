# ADR-005: 高度/法线只能有一个真相源,混用前必须一致性校验

> 状态: 现行 · 类型: 决策 · 更新: 2026-07-03(同日修订:初版误设前提"法线由扩散模型绘制",实际为显卡推理生成,决策据实改写)
> 📖 人话: 高度图和法线图如果来自两次独立的 AI 推理,它们对立体形状的"意见"会不一致,shader 把两者混在一起就永远调不干净。规则:只信其中一张,另一张用脚本推导或先做校验。

## 背景

作者的资材流程:平面图由 AI 生成,高度图/法线图用模型在本地显卡推理得到。2026-07-03 对 centerpiece 资材做逐像素对比发现:推理高度图与推理法线图的 R 通道相关系数 **-0.33**(方向相反,X 轴疑似翻转)、G 通道仅 +0.33(弱一致)、法线 G 均值 140(系统性偏置,疑似原画光影被误读为坡度)。shader 同时消费高度(视差/AO/厚度)与法线(光照),两份互相矛盾的形状描述叠加,是"资材单看没问题、组合起来效果发闷"的头号嫌疑。

## 决策

1. 高度图/法线图**允许**模型推理生成,但两者只能有一个真相源:
   - 首选:只推理一张(高度或法线),另一张用 `npm run assets -- normal` 从高度推导
   - 或:两张都推理,但接入 shader 前必须跑 `npm run assets -- check` 一致性校验(相关系数 + 轴向翻转检测),不达标不入库
2. 通道打包(HRBA / Mask)一律走 `npm run assets`,不手工合成
3. diffuse 生成时提示词要求平光/albedo,避免烘焙光影造成双重光照

## 理由

- 两个独立推理模型对同一平面图的立体理解必然不同;法线方向约定(X/Y 翻转)也因模型而异
- 脚本推导保证高度↔法线数学上严格一致,消除"效果不好是资材还是 shader"的归因不确定性
- 校验工具把"凭感觉争论"变成可复现的数字

## 后果
