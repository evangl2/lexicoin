# 卡片防身与存活周期系统 (Durability Lifecycle)

为了解决随着游戏进程加深，物理画布空间里被旧卡堆积填满的问题，Lexicoin 设计了一个精密的卡片防身（即“耐久度”/Durability）生命周期循环机制。卡片在每次成功协助合成单词时都会产生自然的磨损。

## 1. 存储与实体记录 (Storage & Persistence)
这种持久的耐久度损耗状态并不与表示“该词是什么”（`SenseEntity`）的全局不变结构体挂钩，而是独属于玩家目前手中持有的那张实卡实例。
它与玩家每一次具体的获取操作深度绑定。当玩家合成出或补回一个词条时，一条对应的耐久度子记录会被插入并维护在基于 IndexedDB (使用 Dexie 封装) 的专属资产层 `CardInventoryRepository.ts` 当中。记录包括该卡片的持久唯一识别（`uid`）、所属的游玩语言选项以及动态计算后的剩余耐久（`durability`）。

## 2. 耐久消耗的核心规则 (Durability Alterations)
这一环由前端交互中心 `useSynthesis.ts` 的业务流发起。
*   **新发现 (New Discovery)**：如果大模型反馈给服务端一段全新、不曾见闻的外语组合，该前端词条诞生时将自带 **100满值** 的基础耐久度。
*   **成功消耗 (Successful Synthesis)**：每当两张置于阵法中的子卡成功被识别并催化衍生出一张母卡时，这两张参与牺牲的子卡必须且必然承受耐久度扣除（这由规则表内的 `DURABILITY_SYNTHESIS_COST` 强制计算）。
*   **失败阻断 (Failed Synthesis)**：若玩家胡乱合成导致后端大模型或规则引擎判定失败（即词条无法组合），为了防范非恶意的试错成本过高，系统将中止一切耐久损耗逻辑。源卡片原封不动。
*   **双卡合击/重复还原 (Duplicate Forcing)**：若合成的终点指向了一张玩家**此时此刻已经在画布上持有**的卡片，系统不会无脑生成第二张雷同的物理卡，而是利用这个机会执行一个特殊的 `restoreOnDuplicate` 机制。这会将那张旧卡片当前摇摇欲坠的耐久度重新灌注回复至接近极限值的水平。

## 3. 剥离与销毁 (The Durability Controller)
后台默默运行的 `DurabilitySystem.ts` 接管了每次生命消耗后的边界阈值审查。
当在一次合并不幸使任意源卡片的剩余寿命触及或低于绝对零值时，该中心控制器便执行一套三连剔除操作：
1.  物理销毁：直接通知 `CardInventoryRepository` 执行 `delete` 方法彻底从玩家资产表中抹杀掉该记录条目。
2.  事件广播：调用全服通讯总线 `MessageBus` 发出携带该卡参数的广播令牌 `CARD_DEPLETED`。
3.  渲染卸载：在 React 图形树下，捕捉到该信号的监听钩子如 `useCardManager.ts` 等会将原本存活在视口内的前端悬浮窗瞬间抹去清空。

## 4. 图形展现 (UI Representation)
关于当前卡片血量的展示逻辑，位于物理画板底层结构的 `CardVisual.tsx` 内。
依靠 React 组件的挂载效应，每张小卡片自身携带一个实时的订阅器，并指向 `CARD_DURABILITY_CHANGED` 分支事件。
一旦察觉到自己受累，内嵌在左侧或四周通过 `framer-motion` 驱动的柔滑高度动画便会动态收缩色条比例。这为玩家打造了一个不需要枯燥数字展示也能传达“即将过期”这一危机信号的强视觉交互防线。
