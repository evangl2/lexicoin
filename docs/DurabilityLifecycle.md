# 卡片记忆模型与检索系统 (Memory Model & Retrieval Lifecycle)

> 修订记录:2026-07-05 —— 依据 [ADR-007](decisions/ADR-007-memory-model-and-review.md)《记忆模型取代耐久度》整体重写。原"耐久度(Durability)"机制(按合成次数扣减、归零删卡)已定案退役,本文档描述取代它的目标设计。**现状**:本文档为待实施规格,`DurabilitySystem.ts` / `CardInventoryRepository.ts` 等现行实现仍是旧机制,迁移次序见 [strategic-command.md](strategic-command.md) §2。

为了解决"随着游戏进程加深，物理画布空间里被旧卡堆积填满"这一原始问题，旧方案用的是消耗品经济（耐久度扣减、归零销毁）。ADR-007 指出这个方案有两个根本缺陷：它误伤"用同一个词探索不同搭档"这种应被鼓励的行为，且归零删卡与"正反馈优先"的核心哲学（GDD_Grimoire.md §1.2）冲突——玩家亲手学会的词不该被系统物理抹除。

新方案把"防止堆积"和"制造损耗感"拆成两个独立问题，分别用**新颖度经济**和**记忆模型**解决。

## 1. 新颖度经济（取代"耐久消耗"防刷职责）

合成结果区分首次组合与重复组合：

- **首次组合**：全额奖励（XP、发现记录、新卡实体化）。
- **重复组合**（`SynthesisResult.cached === true`）：不发任何奖励，仅返回结果。

刷同一配方 → 零收益，刷子行为被经济学而非物理销毁解决；一词多搭档的广泛探索 → 每次都是新组合，全额收益。辅以"每卡每日记忆增益封顶"（见下）防止短时高频操作绕过限制。

## 2. 记忆模型（取代"损耗与紧迫感"职责）

每张卡（Sense × 玩家）只存两个字段，不记录操作历史：

```
stability: number        // 记忆稳定度，单位约等于"天"
lastRetrievalAt: number  // 上次成功检索的时间戳
```

**当前记忆保持率是算出来的，不是存出来的**（惰性计算，查询/渲染时求值，不需要定时器）：

```
R = exp(-(now - lastRetrievalAt) / stability)   // 0~1
```

### 2.1 检索事件与稳定度更新

检索事件发生时，`stability` 按以下规则更新：

```
成功检索(质量 q): stability ×= 1 + k · q · (1 - R)   // (1-R) 项即间隔效应本身
失败检索:         stability ×= 惩罚系数(建议初值 0.7)
```

`(1 - R)` 项是这个模型的核心：越是快要忘记时成功回忆，稳定度涨得越多；刚检索过就再检索，几乎不涨——这正是间隔重复起效的机制。

### 2.2 检索事件权重表（设计杠杆，数值可调）

| 事件 | 质量 q | 说明 |
|---|---|---|
| 魔典填词且评级 ≥ C | 按评级换算 | 最强检索：带产出、带评判的主动检索 |
| 复习装置 / Echo 回放答对 | 满 | 纯检索（见 [GDD_Grimoire.md](grimoire/GDD_Grimoire.md) §8.5.2） |
| 合成中使用该卡 | 低，每卡每日封顶 | 主动使用但无检索压力 |
| 被动曝光（看到 / hover） | **0** | 红线：被动曝光不算记忆练习，不可破例 |

### 2.3 风化态（取代"归零删除"）

`R` 长期低于阈值的卡片进入**风化态**：视觉上褪成剪影、沉入档案，但**不删除**。可通过再次遭遇该词（合成产出、Echo 抽中等）唤醒，唤醒后 `stability` 按检索事件正常更新。玩家亲手学会的词永远不会因为系统判定"太久没用"而消失。

## 3. 画布呈现设计律：位置属于玩家，外观属于系统

（决策依据见 ADR-007 §4，此处摘录供实现参考）

- **否决**任何按记忆状态自动分区/自动挪动卡片的方案（如按"新词/记忆/复习/遗忘"四象限自动归类）——位置一旦编码系统状态，卡片就会随状态迁移，玩家的空间记忆钩子（"那个词在火山旁边"）随之失效；
- 记忆状态只驱动**卡片外观**（饱和 → 褪色 → 剪影），不驱动位置；
- 全局记忆地图需求由**记忆透镜**（相机层滤镜，按键切换查看全局 R 分布）满足，不新建位置系统；
- 玩家可自行圈地命名分区，系统只做注解（如显示"该区 38% 正在褪色"），永不代玩家移动卡片；
- 这是 Pixi 重构 Stage F 坐标契约的设计输入：**玩家摆放的卡片位置是神圣数据，持久化精度按学习功能而非 UI 状态对待**。

## 4. 待实施事项

- 三处检索事件挂钩（魔典提交、复习/Echo 回放、合成使用）；
- 合成奖励逻辑接入 `cached` 判断（新颖度经济）；
- `DurabilitySystem.ts` 的耐久扣减/归零删除逻辑退役，替换为风化态判定；`CardInventoryRepository` 增加风化态字段与唤醒逻辑；
- 渲染层 R → 外观映射（Stage F/K 输入）与记忆透镜（滤镜视图）；
