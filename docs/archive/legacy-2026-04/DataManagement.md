# 数据管理与存档机制 (Data Management: Export & Import)

Lexicoin 大量依赖于客户端本地运行的轻量级状态架构。与其将玩家的学习词汇堆积在随时可能断网的远端云服务器上，整套系统选择了彻底的离线自治理念。借助底层的高性能 IndexedDB 库 (`db.ts` 与 Dexie v4 引擎)，跨越多表的庞大多维数据——坐标位移、词汇记录、用户属性与动态配置等，都能在浏览器环境里安全地自我运作。

## 1. 离线存储矩阵图 (Local Storage Schema)
为了承载这样一款兼具教育应用和重体力前端界面的游戏体验，Lexicoin 构建了 7 大数据表群：
1.  `gameData` - 维持核心系统配置信息的承重体。
2.  `senses` - 记录由大模型驱动下生成的，全局唯一定义不变的文字实体库。
3.  `visuals` - 对外表层封装的可视化属性集，如生成的图片、状态标识缓存。
4.  `devices` - 放置场景周边互动的机制组件数据存储（如物理画布上的复合魔法阵圈）。
5.  `canvasPositions` - 实时物理坐标位移跟踪表，确保重启网页时所有的卡牌能完美定格在退出前的位置。
6.  `cardInventory` - 管理当前卡堆体积数目及其处于动态削减过程内的寿命值。
7.  `synthesisLog` - 最为关键的全维历史追索日志表，将玩家从 A1 门槛迈入深层语言合成探索所触发的生成溯源事件彻底封存记载。

## 2. 存取与移植引擎 (Export / Import Methodology)
基于安全与进度不丢失原则，玩家能随时将其硬件内积攒的心血词库一键迁往别处。这种基于独立模块包装的机制被称为 `ExportImportService.ts`。

### A. 导出剥离逻辑 (Export Operation)
当通过 UI 前端调用 `exportToFile` 分支接口后，此工具类函数会彻底遍历并封存整个状态树：
1.  获取并序列化由 Zustand `useGameStore` 掌舵的当前动态虚拟内存对象 `player`。
2.  对齐底层的 `IndexedDB` 队列发号强制轮询查询指令，将前述 7 大集合中的庞大数据实体并行抽调而出。
3.  混合封装以上所有结果对象并在此处刻印版本记号 `schemaVersion=1`，合成一颗标准、跨平台的纯 JSON 结构果实。
4.  借助于原生提供的锚点隐式下载技术触发自动挂载，把生成的包更名为形如 `lexicoin-backup-年-月-日.json` 的实物备份档案推送给玩家留存。

### B. 覆写与注血导入 (Overwrite & Import Operation)
对于把外部保存的历史时刻重注回机器这项任务，导入环节 `importFromFile` 被赋予了不留情面的全量清空准则，旨在杜绝 React 在渲染周期中的脏数据污染漏洞事件。
1.  **协议检测 (Schema Check)**：在拆包的第一顺位，读取比对该快照文件的 `schemaVersion` 版本识别号。若与当前代码校验锁不相称则报错。
2.  **暴力洗库 (Scrub DB)**：调度异步锁清道夫线程对所有前朝遗老的 7 个存根目录执行无差别物理 `clear` 命令。
3.  **高速倒灌 (Bulk Insertion)**：接住那一大块历史记录的集合，分发给 `bulkAdd` 以万计数据包进行毫秒级灌装入库。
4.  **宿主的接管同步 (React Synchronization)**：触发全局挂载总线的钩子将上浮出的存档玩家参数强行更迭回核心 Zustand 并更新 UI 模型。
5.  **内存重启 (Hard Reset)**：一切注血结束时，代码向渲染框架发出不可逆的重载通告。浏览器将执行 `window.location.reload()` 动作来切断所有的陈旧函数引用对象链，使得画面在下一次眨眼便精确且彻底地展现出备份档当时的原始风貌与物理阵型。
