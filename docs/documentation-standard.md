# 文档规范(Documentation Standard)

> 状态: 现行 · 类型: 流程 · 更新: 2026-07-03
> 📖 人话: 这份文件规定项目文档分几类、放哪里、怎么写、什么时候必须更新。所有 AI 会话都要遵守。

## 0. 为什么需要这套规范

本项目由无编程经验的作者 + 无状态的 AI 会话共同开发。代码对作者不可读,AI 每次会话都从零开始——**文档是唯一跨会话存续的项目记忆**。文档不透明,项目就是黑盒。

2026-04 曾有一套 `_meta/` 审计轮换制(定期巡检文档新鲜度),已失败废弃。失败原因:更新靠"记得去审计",与写代码脱节。本规范改为**随手同步制**:哪个会话改了代码,哪个会话当场改文档,写进会话协议强制执行(见 [workflow/session-protocol.md](workflow/session-protocol.md))。

## 1. 文档分类与目录

| 类型 | 目录 | 回答的问题 | 例子 |
|---|---|---|---|
| 架构 | `docs/architecture/` | 代码**是什么**样、怎么协作 | 模块地图、数据流、坐标系 |
| 决策 (ADR) | `docs/decisions/` | **为什么**这么做 | 为什么不换 Godot |
| 设计 (GDD) | `docs/grimoire/` | 游戏**应该**是什么样 | 玩法规则、数值、Persona 设定 |
| 流程 | `docs/workflow/` | 开发**怎么进行** | 会话协议、验证清单 |
| 指南 | 就近放在专题目录 | 具体任务**怎么操作** | Assets-guide、排错手册 |
| 归档 | `docs/archive/` 或各目录 `archive/` | (历史,只读) | 废弃方案 |

**真相分工**:代码是"是什么"的真相之源(架构文档与代码冲突时以代码为准,并修文档);文档是"为什么"和"应该是什么"的真相之源(ADR/GDD 与代码冲突时,是代码错了)。

## 2. 文档头格式(必须)

每份现行文档的第一行标题之后,紧跟一个两行引用块:

```markdown
> 状态: 现行|草稿|已归档→[替代文件](路径) · 类型: 架构|决策|设计|流程|指南 · 更新: YYYY-MM-DD
> 📖 人话: 给初学者的一两句白话说明,这份文档讲什么、什么时候需要读它。
```

- `状态` 让 AI 一眼判断可信度;`更新` 是最后一次实质修改日期
- `📖 人话` 是给作者的窗口,禁止术语堆砌。这一行照顾人类,其余部分以 AI 检索效率优先

## 3. 生命周期规则(铁律级)

1. **单一入口**:AI 的阅读路径固定为 `CLAUDE.md → docs/INDEX.md → 具体文档`。新文档**必须**在 INDEX.md 登记,否则视为不存在
2. **同会话同步**:改了代码结构/行为/约定的会话,收尾时必须更新对应文档和 INDEX 状态(见会话协议)。禁止"以后再补"
3. **过期即归档**:发现文档与现实不符,要么当场修正,要么把状态改为 `已归档→指向替代`。**禁止让过期内容以"现行"状态留存**——过期文档比没有文档更危险
4. **归档不可改**:`archive/` 内的文件永不编辑,只作历史参考
5. **决策必留痕**:凡是"影响超出单个文件、未来可能被质疑"的选择(选型、禁令、架构方向),必须写 ADR。AI 不得推翻现行 ADR;认为决策错了,向作者提出,经同意后写新 ADR 并把旧的标记为"被取代"

## 4. ADR 写法

文件名 `ADR-NNN-短横线摘要.md`,编号递增、永不复用。模板:

```markdown
# ADR-NNN: 标题

> 状态: 现行|已被 ADR-MMM 取代 · 类型: 决策 · 更新: YYYY-MM-DD
> 📖 人话: ……

## 背景
(当时面对什么问题,有哪些备选)

## 决策
(选了什么,一句话)

## 理由
(为什么,列要点)

## 后果
(接受了什么代价,衍生出什么规则/文件)
```

保持短(30 行内)。ADR 记录"为什么",具体规则细节放对应规范文档并互相链接。

## 5. 存量文档处置(渐进迁移)

- **现行有效**:`refactor-pixi/`(roadmap、各指南)、`grimoire/` GDD、`prompts/`
- **停用**:`_meta/` 审计体系(由本规范 + INDEX.md 取代);`feel/`、`perf/`、`entropy/`、`refactor/`、`params/` 六个 agent 目录冻结为历史记录,不再写入
- **待迁移**:root 平铺的约 28 份系统文档,大部分描述已卸载的旧 React UI。处置规则:**哪个会话碰到哪个模块,就顺手处置该模块的文档**——数据层文档(store/schema/pipeline 类)核对后迁入 `architecture/` 并补文档头;纯旧 UI 文档(CompactMode、MergeSplit 等)在对应功能于 Pixi 重建时归档
- 迁移进度以 [INDEX.md](INDEX.md) 中的状态标记为准,不另设进度表
